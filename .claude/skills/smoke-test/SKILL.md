# エディタ再生スモークテスト

Unity MCP でエディタを再生し、UI 操作・スクリーンショット・LLM 対話でアプリの挙動を確認する。

## プライバシー原則（最優先・違反禁止）

- **API キー・エンドポイント URL・llm_config / PlayerPrefs の生値を読まない・return しない・ログに出さない**
- LLM 設定パネル・音声設定パネルを開いた状態のスクリーンショットを撮らない（キー欄が映るため）
- LLM 設定に問題がありそうな場合（接続エラー等）、**設定値を調査せず、テストを中断してユーザーに設定確認を依頼する**
- 設定の判断に使ってよいのは機微でない値のみ: `apiType`（enum）、キーの有無を返す bool（HasDefaultApiKey 等）

## 1. 再生開始前の確認

- コンパイルエラーがないこと（read_console）
- **LLM プロバイダーの確認（再生前に必須）**: 保存済み設定から **apiType のみ**を取得する
  （config オブジェクト全体を return しない。例: `LLMConfigManager.Load()?.apiType` の値だけ返す）
  - **Ollama / LMStudio（ローカル）** → そのまま進行してよい
  - **それ以外（OpenAI / Claude / Gemini / Dify / WebLLM）** → 従量課金・クォータ消費の
    可能性があるため、**再生開始前にユーザーへ確認して許可を得る**
  - ※ 本アプリは起動時に必ず帰宅処理（LLM リクエスト1回）が走る仕様のため、
    「再生するだけ」でもリクエストが発生する。確認は再生前に行うこと

## 2. 再生と起動待ち

- `manage_editor action=play` → `Time.timeSinceLevelLoad` で起動を確認
- VRM 読み込みと帰宅処理があるため、数秒待ってから操作を始める
- 起動直後に帰宅メッセージが表示されるのは仕様（異常ではない）

## 3. テスト操作

- **UI 操作**: コンポーネント API 経由で行う（ユーザー操作と同じイベント経路を通す）
  - トグル: `toggle.isOn = 値`（setter が onValueChanged を発火）
  - ボタン: `button.onClick.Invoke()`
  - 入力欄: `inputField.text = "..."` → 送信処理の呼び出し
- **スクリーンショット**: `ScreenCapture.CaptureScreenshot(絶対パス)` でスクラッチパッドに保存
  → Read ツールで画像を見て状態を確認する。書き込みはフレーム末なので撮影と読み取りは別呼び出しで
- **状態の直接確認**: ChatManager / 各コントローラーの public プロパティを読んでよい（機微値を除く）
- **ログ確認**: read_console で warning / error を確認

## 4. LLM 対話テスト

- チャット入力欄に text を設定し、送信ボタンの onClick.Invoke() で送信（人間と同じ経路）
- 応答は「スクリーンショット」「read_console」「ChatManager の状態」で確認
- 送信回数は必要最小限に。連投テストが必要な場合は回数をユーザーに事前提示する

## 5. 終了処理

- テストで変更した UI 状態（モード切替等）を元に戻す
- **PlayerPrefs に保存される設定は原則テストで変更しない**。やむを得ず変更した場合は必ず元の値に戻す
- `manage_editor action=stop` で再生終了
- 再生の出入りでドメインリロードが発生し、instance ID が変わり MCP ブリッジが瞬断する
  ことがある → 失敗したら少し待ってリトライ

## 6. 報告

- 実施した操作・確認できたこと・気になった点（想定外のログ、表示崩れの可能性など）を報告
- 表示・グラフィックの調整はユーザーの領分。「何が起きているか」の判別と報告に徹する
